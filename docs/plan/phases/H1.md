# H1: Go hygiene — defensive nil checks

**Goal:** remove defensive nil checks that make impossible states disappear silently (returning a zero value, `nil, nil`, or doing nothing), so programming errors surface where they happen instead of as wrong results later. Write the rule down so agents stop adding them.

**Why:** generated Go code tends to accumulate `if x == nil { return }` guards. Inside validated boundaries they hide bugs; the right behavior is an explicit error at a trust boundary, or a loud failure for an unreachable state.

**Exit:** every nil check in `internal/` is classified and either justified or fixed; behavior changes are test-first; the rule is in `AGENTS.md`, `docs/development-guide.md` and `.claude/agents/sw-reviewer.md`; `check` and `persistence` pass.

## Rule (to be written into the guides)

- Check for nil only at trust boundaries: external input, optional values that are part of the contract (a pointer or map that may legitimately be absent), and dependencies passed to constructors. A failed check returns an explicit, wrapped error — never a silent zero value.
- Inside a boundary, rely on invariants established by validated constructors (`New*`, `Reconstitute*`); do not re-check what the type already guarantees.
- An "impossible" nil fails loudly: an error naming the broken invariant, or a panic with a message only where the state is genuinely unreachable.
- Never `if err != nil { return nil }`, never `return nil, nil` for "not found" (use a sentinel such as `ErrNotFound`), never an empty `default` that swallows an unexpected case.

## Tasks

- **H1-A Inventory** (reviewer subagent, read-only): list every `== nil` / `!= nil` check, `return nil, nil`, swallowed error, and empty `default` in `internal/`, classified as boundary (keep), contract-optional (keep), redundant after a validated constructor (remove), or silent swallow (fix). `go vet` plus an optional `nilaway` run as signals only.
- **H1-B Fixes** — owns the files listed by H1-A, split by package if large. Remove redundant checks; turn silent swallows into explicit errors with a RED test first whenever behavior changes.
- **H1-C Guidance** (orchestrator): add the rule to `AGENTS.md` and `docs/development-guide.md`, and add a "defensive nil checks" item to the `sw-reviewer` checklist.
