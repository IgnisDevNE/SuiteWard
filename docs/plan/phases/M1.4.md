# M1.4: GitHub synchronization

**Goal:** discover and reconcile pull requests over outbound GitHub access only, within a bounded API budget, with a local MCP endpoint that lets an agent request a sync and read status.

**Decisions:** D-SYNC (defaults accepted; numbers confirmed by S1), D-GITHUB-ACCESS (accepted 2026-10-11 from the S1 findings). D-IDENTITY stays open: the GitHub settings of this phase are an interim operator configuration (see the [GitHub contract](../../contracts/github.md#configuration-interim-m14)).

**Exit:** a configured repository's PRs, heads, comments and protected files are synchronized on schedule and on MCP request; omitting MCP calls still converges; API use stays within budget; restart catches up.

## Tasks (refined 2026-10-11)

The contract is [github](../../contracts/github.md); settings are in the [runtime contract](../../contracts/runtime.md). Tests use recorded fixtures and an `httptest.Server`; no task outside the orchestrator holds the App key.

| --- | --- | --- | --- |
| 0 | **C0 Contracts** | the GitHub contract, the runtime settings, D-GITHUB-ACCESS, this page | orchestrator |

| — | **Live test** | opt-in test against the S1 test repository with the real App key | orchestrator only |

- **A1** — the App JWT (RS256, standard library) and installation tokens with an explicit permission map and repository list, reused until five minutes before expiry, behind an injected clock; the token never reaches an error, a log or `String()`.
- **A2** — conditional GETs with an ETag cache scoped to the token identity, the per-process budget at half the rate limit, and typed errors.
- **A3** — open PRs, PR comments, and an `inventory.Tree` over the git trees API (links and submodules typed; a truncated tree is an error; blobs read only when asked).
- **A4** — the GitHub settings (all or none), the composition of the adapter in `serve`.
- **B** — per-repository scheduling, coalescing, the shared budget, restart catch-up.
- **C** — `sync` and `status` only, local token, no approval or administration capability.
- **Live test** — asserts first the permissions S1 did not measure with a narrowed token on a private repository (`GET /pulls/{n}`, commit reads).

The phase changes what runs, so it is verified on both targets. Owner steps: add `phase/M1.4` to the deployment branch rule of the `remote-poc` environment, and place the App key on the host and on the development machine for the live test.
