# M1.10: Code review and maintenance

**Goal:** the codebase is reviewed end to end and left organized before the security gate. That means no dead code, no hidden impossible states, and no dangerous complexity left unaddressed, with the same product behavior.

**Decision:** owner request, 2026-10-19. The security gate comes after this phase, on clean code.

**Rules:**
- **No behavior change.** Every refactor keeps the existing tests green. A change that would alter behavior is a finding for the owner, not a refactor.
- **Defects found during the review follow the [TDD rule](../../tdd.md).** The failing test is committed first.
- **This repository is governed by SuiteWard.** Refactors that touch protected tests need the owner's approval of the final revision, so fixes are batched to keep the approval rounds few.
- **Least code:** a refactor deletes or merges code more often than it adds abstractions. The [nil-check rule](../../development-guide.md#nil-checks) applies.

**Exit:**
- **Dead code:** no unreachable or unused functions, types or payload fields, outside documented compatibility shims, each of which carries its removal condition.
- **Nil handling:** no `return nil, nil`, no swallowed error and no empty `default` that hides an impossible state. Nil checks exist only at trust boundaries, and each returns an explicit error.
- **Complexity:** every function above the agreed cyclomatic or cognitive threshold (set during planning, from the measured baseline) is refactored or recorded with the reason it stays. The hotspots (complexity × recent churn) are reviewed first.
- **Duplication:** duplicated helpers are merged.
- **Carried findings:** the M1.9 low findings ([backlog](M1.9.md#backlog-carried)) are fixed or explicitly kept with a reason.
- **Checks:** `check`, `persistence` and `-race` pass. Coverage does not drop below the current level.

## Method (planned at phase start)

1. **Baseline.** These tools only measure, and none of their output counts as verification evidence:
   - Memtrace: `find_dead_code`, `find_hotspots`, `find_most_complex_functions`, `find_duplicate_code`;
   - the linters already in `golangci-lint`;
   - a nil and error scan.

   The baseline becomes the phase's task list.
2. **Review by area.** Independent `sw-reviewer` passes cover these areas:
   - `domain`;
   - `application`;
   - `adapters` (postgres, github, river, mcp);
   - `app` and `config`;
   - scripts and deploy.

   Each pass reports ranked findings.
3. **Tasks.** One worktree and one task per area or finding cluster, implemented by `sw-implementer` and reviewed by `sw-reviewer`.
4. **Close.** A whole-phase review and the advisor. Then one integration PR and a patch release (`v0.1.2`), if anything shipped changes.

2. **Permanent linters** in `.golangci.yml`:

3. **Tests are in scope** for refactoring, with care. No assertion is removed or weakened, and the reviewer checks it.
4. **Delete the application functions that no production path calls**, `governance.Correct`, `ReviseProposal` and `Promote`, and rewrite the conformance suites onto the production paths (`Bootstrap`, `ProposeBaseline`, `AssessHead`, `PromoteMerge`). 5. **An impossible error fails loudly.** The `AddPatterns` branch at `runneruncovered.go:126-129` returns an error instead of logging and skipping the comment. This applies the nil-check rule.
   - **Precondition:** a test first proves that no head path can reach that branch, because its input is the validated canonical plus the constant runner patterns. If any head input can reach it, the change is not made and the finding goes back to the owner: a loud error there would fail the checks job on every run, the defect class E14 fixed.
   - **Out of scope:** the `AddExcludes` branch at `:133-135`. Its input comes from head paths, so dropping the ignore choice there is degradation on input, not a hidden impossible state.
6. **Double-check every suggestion.** A tool's output is a lead, never evidence. A finding becomes a task only after someone has read the code and every reference to it: function values, suite tables, build tags, interfaces, and test-only use. Rows marked *(provisional)* below were classified from the score and the context, not from the body, and wave 1 reads them before any brief cites them.

### Owner decisions from wave 1 (2026-10-19)

7. **Hidden characters in a quoted declaration.**
   - **The problem:** a declaration shown for copying could carry invisible characters (bidi, zero-width, control) from a comment of the author's `.suiteward.yml`.
   - **The rule:** that declaration is refused, and the comment offers the pattern line alone, as it already does for a declaration that is too large.
   - **Where:** `ValidateInvalidSource`, `ValidateScopeNotice` and `ValidateRunnerUncovered`. Only `\n` and `\t` are accepted.
8. **Test-only production code is removed or moved to test files:**
   - `postgres.Store.Seed` moves to a `_test.go` file;
   - `governance.Tx.Enqueue` and its postgres implementation are deleted. It is ADR 0005's transactional enqueue, which the README also advertises. The owner confirmed the deletion on 2026-10-19, after being told: M4 amends ADR 0005 and the README to say that the outbox carries the transactional guarantee;
   - unused result fields are dropped (`ConsentResponse.Committed`, `PromoteResult.Committed` and `.Record`; the unused `PromotionEffect` state);
   - the checks that only the deleted functions could reach are dropped too: the `reviseWithin` guard and the correction not-found branch in `promoteWithin`. M4a verifies each guard's reachability before it goes. The promotion kind-replay compare (`promote.go:115`) **stays**: it can still fire against a consent receipt, so it becomes an explicit `ErrInvalidState` check;
   - the contract is updated. Assertions that tested only these go with them, and each is listed in the task report.
9. **Behavior fixes, each test-first:**
   - **Merges in the same second:** `RecordClosed` accepts a pull merged in the same second as the watermark (`!Before`).
   - **Both impossible branches:** decision 5 applies to the `AddExcludes` branch too. R5 proved both branches unreachable from head input, and a precondition test proves it in the code.
   - **GitHub text:** the GitHub adapter's errors no longer carry GitHub's response text (`Body` and `errorBody` are removed, and `github.md` is updated).
   - **Quoting:** review suggestions follow the quoting style of the list they extend.
10. **Infrastructure cleanup:**
    - `deploy.yml` deploys from `main` only;
    - the S1 removal section leaves `deploy/HOST.md`;
    - `dev.ps1 persistence` gains `-race`, and `test-go.ps1` follows.
