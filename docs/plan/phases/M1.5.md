# M1.5: Owner and trust

**Goal:** connect a verified human owner, enroll the TOTP secret the agent cannot reach, classify the installation tier honestly, and verify that GitHub actually enforces the required checks.

**Decisions:** D-TRUST (ADR 0027), D-IDENTITY, D-TIER, D-CHECKS and D-PROTECTION (all accepted 2026-10-13), D-GITHUB-ACCESS (amended 2026-10-13: Administration read); ADR 0016 amendment (verification only in the MVP).

**Exit:** a setup flow binds the owner's GitHub identity, enrolls TOTP, records the tier (isolated or co-located) and shows it in status. Protection verification reports one of these, each with manual instructions:
- `enforced`, with the `ruleset-bypass-unverified` caveat when a ruleset is involved;
- `findings` (`missing-contract-check`, `missing-test-check`, `not-up-to-date`, `admin-bypass`);
- `enforcement-unavailable`, for example a private repository on GitHub Free;
- `unknown`.

The ruleset had a "Repository admin" bypass actor during the second run (visible in GitHub's settings page), and the API still answered 0 bypass actors. ### Task details

- **A1 (TOTP).** RFC 6238 with SHA-1, 6 digits and a 30 s step; stdlib only.
  - API:
    - `SecretBytes = 20`;
    - `NewSecret(io.Reader) ([]byte, error)`;
    - `URI(secret, issuer, account) (string, error)`, which builds `otpauth://totp/…` with `secret` (base32, no padding), `issuer`, `algorithm=SHA1`, `digits=6` and `period=30`;
    - `Step(time.Time) int64`;
    - `Code(secret, step) (string, error)`;
    - `Verify(secret, code, at, tolerance int) (step int64, err error)`, which returns the matching step and errors with `ErrInvalidCode` or `ErrInvalidSecret`, and compares codes in constant time (`crypto/subtle`).
  - Replay is the store's job, not this package's.
  - Tests: the RFC 6238 Appendix B SHA-1 vectors, the tolerance edges, malformed codes and secrets, and the URI.
- **B (tier).** The setting follows the runtime table: default `co-located`, any other value is an error.
- **A2 (owner store).** Follows the persistence contract.
- **C1 (protection reads).** The protection token requests exactly `{metadata: read, administration: read}` through the existing `appauth` and shares the one `rest.Budget`. `readPermissions` and the synchronization map stay unchanged.
- **C2 (evaluator).** Follows D-PROTECTION:
  - findings over both sources together;
  - "pinned" means integration or app id equal to the App id;
  - `enforcement-unavailable` is inferred from a private repository plus `RulesForbidden`;
  - an `appauth.ErrPermissionsMismatch` on the protection token gives `unknown`, with the instruction to grant Administration read.
- **A3 (setup).** Follows the runtime contract. It reads stdin, so the HOST.md step uses `podman exec -it`. The owner must be a `User`.
- **C3 (protection job).** Every 15 minutes; results are stored per repository and replaced each time.

## Outcome

Completed 2026-10-13, merged into `main` as `b470a4f` (PR #21).

**Delivered**
- `internal/domain/totp`: RFC 6238 codes, verification within a tolerance, and `otpauth` URIs.
- `internal/application/owner` with migration `00012`:
  - one owner per instance;
  - an enrollment generation that points at the governing `setup-<n>` policy revision;
  - consumed steps that are never purged;
  - the latest protection result per repository.
- `internal/application/protection`: the pure D-PROTECTION evaluator.
- `internal/adapters/github`: `User`, `Repository` and `Protection` reads.
- `suiteward setup`. It:
  - looks up the owner and the repositories;
  - waits for confirmation before it prints the secret;
  - verifies the code;
  - enrolls atomically;
  - verifies protection.
- `github_protection_check`: runs every 15 minutes within the tick deadline.
- `/status` and MCP report `owner`, the effective `tier`, `tierNote` and `protection`.
- Deployment: `INSTALLATION_TIER` is declared on both targets; HOST.md documents the owner setup; the smoke checks `tier`.

**Evidence**
- The live tests, the co-located target and the remote host, as recorded under Verification.

**Limitations**
- The App cannot see a ruleset's bypass list (the `ruleset-bypass-unverified` caveat).
- A repository that was never read has no protection result yet.
- A protection read still in flight at `JOB_TIMEOUT` fails that run.
- `owner.ProtectionResult` keeps string fields.
- Changing the owner after a Suite exists is refused (D-COMMANDS).
- Orbit ran only A1 (see the [Orbit page](../orbit.md)).
