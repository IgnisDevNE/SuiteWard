# M1.15: installer leftovers, the live findings, scope discovery

**Goal:** close what M1.14 left in the installer, fix what the live checks of `v0.4.0-alpha.2` find (on macOS, by an outside tester, and on Windows, by the owner), and, in parallel and in packages the installer does not touch, answer the owner's scope-discovery questions Q2 to Q4 and read the earlier versions in one step at a merge. The governance of this repository changes only by the D-SELF-SCOPE entries below, approved by the owner like any protected change.

## Owner decisions (2026-10-25)

1. **The phase.** The installer leftovers, the live checks and a wave reserved for the live findings, with scope discovery as the post-MVP track.
2. **`suiteward scope add`** answers the owner's question Q2 (a command to add folders that the suggestion missed): a local command in a checkout, for a user or an agent, that adds patterns to `.suiteward.yml` as text. The change still needs the owner's approval on its pull request.
3. **No reading of config files in this phase** (owner, 2026-10-25, after the S4 study and its review; this replaces the first decision to read them, with a TOML dependency, in every suggestion). Every test directory that a config file named in the study's sample is one the path rules already find, and a configured directory is not a safe suggestion on its own: pandas names its whole package in `testpaths`. A gated reading would have suggested nothing the path rules miss. Detection stays path-only (D-SCOPE-DISCOVERY), and `suiteward scope add` serves the layouts it misses.
4. **`nextMergeVersion` in one read** replaces config reading as the post-MVP task that keeps the agents busy until the live findings: the merge promotion reads the earlier versions of the Suite once, instead of one version per step.
5. **D-SELF-SCOPE, accepted:** `scripts/install_test.sh` and `deploy/smoke_test.sh` join `include`, and `scripts/install.sh` and `deploy/smoke.sh` join `runner`.
6. **D-RESTORE-INPLACE, accepted for the alpha:** the in-place restore stays, with its typed instance id and its safety backup; the recovery mode of ADR 0020 waits with the remote backups.

## Outcome so far

Waves 1 and 2 are merged on `phase/M1.15`. The decisions are in [D-M1.15](../decisions.md#d-m115-scope-discovery-answers-and-the-merge-version-in-one-read), and the live findings of wave 3 are not in yet.

- **S4:** the test-discovery study, [`docs/spikes/s3-test-discovery.md`](../../spikes/s3-test-discovery.md). The owner took config reading out of the phase on its evidence.
- **I1:** on a full screen, the owner question of `enroll` is a page of its own, and the re-enroll text says that setup shows a secret and a URI, not a code to scan. The small-window summary test no longer depends on the length of the temp path. On Windows the setup window gets the program and its exit file intact when their paths hold a space, and a later setup removes the `suiteward-setup-*` folders of earlier windows whose exit file is more than a day old.
- **S2:** `suiteward scope add [--runner] PATTERN...` inserts patterns into the `.suiteward.yml` of the current directory as text, and leaves to the user what it cannot insert safely.
- **D-SELF-SCOPE:** `scripts/install_test.sh` and `deploy/smoke_test.sh` are in `include`, and `scripts/install.sh` and `deploy/smoke.sh` in `runner`. Like any protected change, it takes effect once the owner approves its revision.
- **G1:** a merge reads the earlier versions of the Suite with one `Tx.VersionsHolding`, by manifest digest, instead of one `Tx.Version` per version.

Known limits:
- A failed sweep of the stale setup folders is not reported to the user (a `shortcut:` note in `setupwindow_windows.go`). The setup window is frozen until the live findings, and reporting the failure needs the window to carry a note.
- A pattern that starts with `-` and comes first, such as `-name/`, gets the flag parser's error and not the hint to write `**/-name`. The hint is given for one that follows another pattern.
- The anchor rule of `scope add` covers the key and the list only. The read-back check that follows still compares the three lists with the old declaration plus the new patterns, and leaves the file to the user when they differ.
- A read-only `.suiteward.yml` is refused on Windows, where the replacement fails and the command exits 1, but replaced on Linux.
