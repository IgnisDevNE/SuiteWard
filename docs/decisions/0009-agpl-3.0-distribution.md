# ADR 0009: Open-source distribution under GNU AGPLv3

- **Date:** 2026-09-26
- **Status:** Accepted. Amended 2026-10-17: the grant is `AGPL-3.0-only`, and the M1.8 release applies the notices ([D-RELEASE](../plan/decisions.md#d-release-platforms-versions-license-and-notices)).
- **Scope:** Distribution model and future hosted operation.
- **Origin:** The user selected AGPL-3.0 after discussing permissive licensing and closed derivatives.

## Context

SuiteWard begins as self-hosted open-source software. A paid managed service may follow using the same core architecture. The selected license should preserve source availability obligations for covered derivatives, including the modified network-service case.

## Decision

Use GNU Affero General Public License version 3 as the project's chosen license direction.

Commercial use, paid hosting, and compliant competing services remain possible. AGPL is not a ban on commercial activity. Distribution of covered code carries source obligations; section 13 also requires a modified network-interactive version to offer its corresponding source to its remote users. Purely private modifications do not automatically require public publication. The actual license terms govern these cases. [AGPLv3 text and identifiers](https://spdx.org/licenses/AGPL-3.0-only.html).

This decision selects the family and version discussed as AGPL-3.0. The final grant must explicitly settle AGPL-3.0-only versus AGPL-3.0-or-later before release; these are distinct identifiers and the conversation did not choose between them. [SPDX distinction](https://spdx.org/licenses/AGPL-3.0-only.html).

No proprietary extension, alternate commercial license, contributor agreement, or copyright assignment is implied by the possibility of managed hosting.

## Alternatives and consequences

- **Apache-2.0 or another permissive license:** would allow broader closed derivative distribution, which did not match the user's preference.
- **A noncommercial or source-available restriction:** would change the intended open-source distribution model and was not selected.

License notices, corresponding-source access, and dependency licensing must be included in release preparation. Dependency and deployment decisions must be compatible with the license actually applied.

A future paid service remains an operational and business choice. It does not require changing the provider-agnostic domain or the self-hosted design.

## Open release details

- Final only-versus-or-later grant and copyright notice.
- Actual LICENSE file and package/source notices.
- Source-offer presentation for a hosted deployment where required.
- Contribution terms, if needed.

This ADR records the decision. It does not itself apply a complete license notice to a software release.

## Amendment 2026-10-17

The owner chose `AGPL-3.0-only`, so that adopting a later AGPL version stays their decision. [D-RELEASE](../plan/decisions.md#d-release-platforms-versions-license-and-notices) settles the open release details:
- **The license.** The official text goes in `LICENSE`, with a README notice and no per-file headers.
- **Third-party notices.** They ship in the image.
- **The source offer.** `/status` reports a `source` URL for the exact revision.

Contribution terms stay open.
