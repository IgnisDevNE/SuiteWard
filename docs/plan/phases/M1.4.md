# M1.4: GitHub synchronization

**Goal:** discover and reconcile pull requests over outbound GitHub access only, within a bounded API budget, with a local MCP endpoint that lets an agent request a sync and read status.

**Decisions:** D-SYNC (defaults accepted; numbers confirmed by S1), D-GITHUB-ACCESS (settled from S1 findings before this phase starts).

**Exit:** a configured repository's PRs, heads, comments and protected files are synchronized on schedule and on MCP request; omitting MCP calls still converges; API use stays within budget; restart catches up.

## Tasks (refined after S1)

- **M1.4-A App authentication and read adapter** — `internal/adapters/github/**`: installation tokens, conditional requests, typed reads needed by M1.3–M1.7; recorded fixtures for tests plus an opt-in live test against the S1 test repository.
- **M1.4-B Budgeted reconciliation** — River periodic jobs: per-repository scheduling, coalescing, shared budget, restart catch-up.
- **M1.4-C Local MCP** — `internal/adapters/mcp/**`: `sync` and `status` only, local token, no approval or administration capability.
