# M1.6b: Assessment and check

**Goal:** assess the exact head of each open PR against the canonical contract and publish `SuiteWard / Contract` (D-CHECKS, ADR 0015) through the outbox.

**Depends on:** M1.6a.

Refined when M1.6a is merged. Known inputs:
- PR-head integrity assessments;
- new proposal revisions for protected changes;
- check publication with POST only, because the latest run with the name wins (S1);
- the payload carries a generation instead of a state, so a delayed `success` cannot land after a revoke;
- the check summary includes the installation tier (D-TIER);
- the owner-invalid `failure`.

Backlog from M1.6a verification:
- ADR 0010's other path: bootstrap from the first PR that carries tests, with a readiness check. M1.6a only waits for an initial contract on the default branch (a repository whose default branch has no protected files proposes nothing).
- The approval text "P<n>-R<m> is now eligible for promotion" overstates the outcome when the bootstrap is blocked for another reason (for example an empty inventory); say what actually happened, or say nothing until the promotion is recorded.
- A failing `github_bootstrap` run is visible only in the service journal, because `/status` excludes the job from its counts (seen on the remote host, 2026-10-14). Surface the last bootstrap error per repository.
- A repository removed from `GITHUB_REPOSITORIES` without re-running setup keeps its old `lastSuccess`, so the commands watermark stalls without a warning. Warn, or skip enrolled repositories that are not configured.
- Owner codes were rejected as stale several times with the ±1 step tolerance. Measure whether the window is usable before M1.8.
