# M2.1b: results communication

**Goal:** SuiteWard says what its test runs found, plainly and where the person looks. Every pull request of a repository with an execution profile gets a comment when its runs end; the results of a pull request are on one page with tables; an approved test that a change edits and that fails in its approved version is pointed out; a test runner that stops responding is said at once and can be unblocked; the installer asks which installation instead of taking flags; and every comment, check summary and page text is rewritten in plain language. This repository turns execution on in this phase's own pull request (dogfooding, [D-ROADMAP](../decisions.md#d-roadmap-the-order-after-m21)). It takes the rest of decision 22 of [M2.1](M2.1.md).

## Owner decisions (2026-10-28)

1. **A results comment per head.** A new comment, never edited. The App has `pull_requests: write` and no `issues` permission, and nothing edits comments.
2. **Only where a profile is named.** Every pull request of a repository whose canonical declaration names `execution:` gets one, a pull request with no protected change included. A repository without a profile gets none, since nothing runs there.
3. **General information only on GitHub.** The comment gives the counts and the general situation (for example that an approved test fails on the head and the change edits it, that the receipt meets `fix` and not `refactor`, or that the test runner is not responding), never a test name or a path. The details are on the page it links.
4. **Not responding after about 30 seconds.** A head whose runs wait while no test runner has checked in for about 30 seconds reads "test runner not responding, SuiteWard keeps trying". The Windows test runner restarts about 5 to 10 seconds after a crash instead of 61, as the Linux one already does in 5, so a routine restart never trips it.
5. **Early unblock.** `/suiteward unblock` works as soon as the head reads not responding. A run that a live test runner is working on cannot be unblocked. This amends [ADR 0028](../../decisions/0028-canonical-execution-and-the-receipt.md), where an unblock never lifts a pending run.
6. **An early unblock holds.** When the test runner comes back, the unblocked job is not replaced, and the next push runs as usual. If the pull request is still open then, SuiteWard warns that this head was unblocked and that its tests did not run.
7. **The reason in words for each flagged test,** on the page, from what is already stored: the outcome of each run (`pass`, `fail`, `build-error`, `skip`, `absent`) and the state. No test output is stored or shown.
8. **This repository starts advisory.** Its `.suiteward.yml` names `execution: {profile: go}` with the default levels (`canonical: advisory`, `receipt: advisory`); `required` waits for a later phase, after a few pull requests on the AWS host.

From [D-ROADMAP](../decisions.md#d-roadmap-the-order-after-m21) and decision 22 of M2.1: one page per pull request with tables, the meaning of each state and the reason of each mode's summary; the weakened-test signal; an installer that asks on screen what it can; the remaining plain wording; M2.1's installer leftovers; the documents that contradict each other, first; and the live tests of each phase.

The design is recorded in [ADR 0029](../../decisions/0029-results-communication.md) (task A0). The owner answered its open points on 2026-10-28:

9. **No comment where no run is wanted.** A pull request whose canonical run is off and whose receipt is off or does not apply gets no results comment.
10. **Every unblock holds,** early or after the 2-minute wait: the job is not replaced when the runner comes back.
11. **The counts of an awaiting-approval check wait for every wanted run** (under `canonical: required`), so the check can say how many approved tests the change edits and that fail; no migration.
12. **A second results comment after an approval only when there is something to say:** the set run under the approved version is written unless both it and the earlier set are clean.
13. **The burst after an upgrade or a long outage is accepted:** every open pull request whose runs are final gets its comment.
14. **The pull request page has no diffs:** it shows the file table and links the revision's report, which keeps them.

## Live tests

From this phase on ([D-ROADMAP](../decisions.md#d-roadmap-the-order-after-m21)), with a development build before the pull request, one after another (one test runner per user, and Docker Desktop's engine is shared with WSL):
1. the co-located tier on Windows with Docker;
2. the co-located tier on Windows with Podman, on a Podman machine of its own for tests (never `podman-machine-default`, where A3 runs);
3. the co-located tier on Linux, on a WSL Ubuntu 24.04 distro, with rootless Podman inside it (the install without GitHub seen on 2026-10-29 with Podman 4.9.3; the flow with GitHub waits for the owner);
4. the isolated tier on a throwaway AlmaLinux 9 WSL distro: the sandbox tests and the host step (seen on 2026-10-29 with a development build and no terminal; WSL has no SELinux);
5. last, a Windows test runner started by a real logon.

Seen before the pull request: item 3 without GitHub, and item 4. Items 1 and 2, the flow with GitHub of item 3, and item 5 are left to the owner's acceptance test of the published `v0.5.0-alpha.2` ([Outcome](#outcome)).

The full isolated flow ran on the published `v0.5.0-alpha.2` on the new host, with a new GitHub App, before the merge: the release was cut from the phase head. At the merge the host promoted the second version. This repository's first pull request run by the host is the one that carries the closing docs (task D2).

## Outcome

**Merged and released.** The owner merged [#62](https://github.com/IgnisDevNE/SuiteWard/pull/62) on 2026-10-29 with a merge commit, `dba7a5cb`. The pre-release `v0.5.0-alpha.2` was published the same day (release run 40944747524). It was cut from the phase head `0a5a41d8`, before the merge, for the owner's acceptance test. Its index digest is `sha256:185733808842aace0346b7a0570b3ae88a602ac027e9789bcf7a7dffba77336f`. On the PC, with the pinned `cosign`, `SHA256SUMS` and the Windows binary were verified as signed by `release.yml`.

**The governing host changed.** A1, the AWS host that governed this repository, no longer exists. The owner removed it before the acceptance test, and its history of proposals and versions went with it: `v0.2.0-rc.3` had no recovery key and no backup. A new host governs in its place ([D-DEPLOY](../decisions.md#d-deploy-remote-verification-host)): AWS us-east-2, `t4g.xlarge` (4 vCPU, 16 GiB), 40 GiB of encrypted gp3, AlmaLinux 9.8 arm64 with SELinux enforcing, reached through SSM only. Its history starts at a new bootstrap from `main`.

**Seen live before the pull request** (development builds, 2026-10-29):
- **A throwaway AlmaLinux 9.8 WSL distro** (Podman 5.8.2; WSL has no SELinux): the host step with no terminal ended with exit code 0, twice (the second time over the existing accounts, with the fixes of the whole-phase review), through `runuser` and the test runner account's own user manager; the tagged tests of the sandbox, the `run` package, the verified source stream and the Go profile passed as a user without administrator rights under rootless Podman.
- **A throwaway Ubuntu 24.04 WSL distro** (rootless Podman 4.9.3): a co-located install without GitHub, with no terminal. It first failed, because Podman 4.9 refuses `podman secret create --replace` for a secret that does not exist yet (task F1). After the fix it ended with exit code 0, the test runner ran as a user unit and the service saw it. The sandbox test that expects Podman to report the memory kill fails on 4.9, which does not report it, and the product is right ([D-PODMAN-FLOOR](../decisions.md#open) is open).

**Seen on the new host, before the tag** (SELinux enforcing): the two commands that the host step runs as the test runner's account, with no terminal, `runuser … env -i … systemd-run --user --wait` and `systemctl --user is-system-running --wait`, gave exit code 0 and `running`. The host step of `v0.5.0-alpha.1` had failed on A1 for this reason (task H1).

**Seen on the published `v0.5.0-alpha.2`** (2026-10-29, the new host):
- the host step, every row ok: Podman 5.8.2, the accounts, the metadata rule and the test runner;
- the isolated install, with a new GitHub App (instance `52181acf`);
- `suiteward doctor`: 27 ok, 0 warnings, 0 failures;
- the smoke test passed, the restart included;
- `/status`: protection `enforced`, and the test runner seen;
- only the two loopback ports listening;
- the bootstrap, on a throwaway pull request ([#63](https://github.com/IgnisDevNE/SuiteWard/pull/63)): proposal P1-R1, pinned to `main` at `92277fe3` with 677 protected files (git's own count of the rules agrees), became the first version (V1);
- on #62: the host recorded the owner's approval of P2-R1, and promoted the second version (V2) from the merge commit when the pull request was merged. From here the `.suiteward.yml` of `main` names `execution: {profile: go}`, so this repository's approved tests run on every pull request, advisory (decision 8).

**Not seen live yet** (the owner's acceptance test):
