# M1.6: PR governance

**Goal:** turn trusted PR observations into exact approval and revocation outcomes, integrity assessments, and the `SuiteWard / Contract` check, published durably through the outbox.

**Decisions:** D-CHECKS (settle from S1 findings), D-APPROVAL-CONTEXT, D-TRUST.

**Exit:** on a real test repository, a protected change stays blocked until the owner approves the exact revision with a valid TOTP code; an implementation-only push keeps consent and is reassessed; a protected change creates a new revision needing fresh approval; revocation blocks again; every processed command gets a visible outcome comment.

## Tasks (refined before start)

- **M1.6-A Command parsing and processing** — parse `/suiteward approve|revoke <ref> <code>` from synchronized comments, verify TOTP, process through `ProcessConsent`, publish the outcome.
- **M1.6-B Assessment** — produce integrity evidence for the exact PR head from the inventory; record assessments.
- **M1.6-C Check publication** — compute and publish the check state and summary (including installation tier) through the outbox; stale-publication handling.
