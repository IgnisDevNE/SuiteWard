# M1.14: installer UX refinement

**Goal:** the owner's sprint after the fresh install of `v0.4.0-alpha.1` (2026-10-23). The owner reinstalled SuiteWard from zero on Windows with a Podman machine, as a new user would, and wrote down what got in the way: 25 findings, UX-1 to UX-25. The installer must explain itself, so that nobody needs the install guide open, and [`docs/install.md`](../../install.md) becomes a reference and not a prerequisite. The phase changes the installer's screens and a few defaults. It changes no governance: `.suiteward.yml` and the five invariants are untouched.

## Owner decisions (2026-10-23)

The reasons and the amendments to the earlier decisions are in [D-M1.14](../decisions.md#d-m114-installer-ux-refinement-after-a-fresh-install).

1. **Explanations on the full screen only.** Every question has a page of its own: what it asks, the choices and their trade-off, the recommended one, the default. Plain mode, scripts and agents keep their typed questions.
2. **Arrow keys, with a fallback.** Lists are picked with the arrow keys and multiple choices with Space, with no TUI library. Typed or numbered answers stay where keys cannot be read and in plain mode.
3. **Setup in a window of its own** on Windows (a new console) and macOS (Terminal), while the installer waits on a screen of its own. Linux, SSH, the isolated tier and plain mode keep the hand-over.
4. **The `suiteward` command on Windows:** every printed command names the program as the run reaches it, and the install offers to copy it to the user's folder and PATH, with Yes as the default.
5. **Default ports 27081 and 27091**, for both tiers. A stack that exists keeps its ports.
6. **Verification of the download is optional**, and the guide says so. Nothing else now: no `install.ps1`, no new asset.
7. **The install ends with doctor** in its summary. It never fails the install, so the exit code stays 0.

## Outcome

The phase is merged and released as `v0.4.0-alpha.2`. This is what it delivers, what was checked live and what is still to be seen.

**Delivered.**
- **Questions that explain themselves:** a page for each question, in the SuiteWard colors, with the choices, the recommended one and the default ([install guide](../../install.md#5-install-co-located) and [screens](../../install.md#the-installers-screens)).
- **Arrow keys:** lists and multiple choices, with the typed fallback.
- **The GitHub flow:** the account and its organization look-up, the manifest flow that goes on by itself, the hidden paste, the repositories as a multiple choice, and the ruleset pause that reads the protection back.
- **Setup in a window of its own** on Windows and macOS ([section 6](../../install.md#6-run-setup)).
- **The summary with doctor,** the status address and the way back after an upgrade. Its rows are the tier, the runtime, `Instance` (the id) and `Release` (the version); a window that is too small for all of them keeps the key rows.
- **The command on Windows:** the printed commands, and the copy on the PATH ([section 5.7](../../install.md#5-install-co-located)).
- **Ports 27081 and 27091,** and `suiteward version`.
- **The restore:** a confirmation page and a closing line that says how to bring the canonical level with the default branch ([backup runbook](../../backup.md#3-restore)).

**Checked live** (2026-10-24, Windows 11, a build of the phase head; the owner authorized the TOTP part, run on a backup of the instance that was restored afterwards).
- **The arrow keys and Ctrl-C** at a list, on Windows Terminal and on conhost (the owner, with K0).
- **The setup window on Windows Terminal:**
  - a correct code is accepted, the window closes and the install says enrolled (exit 0);
  - three wrong codes close the window and the red failure page follows (exit 1);
  - a Ctrl-C at the window's closing Enter still counts as the success it was;
  - a Ctrl-C at the installer closes the setup window with nothing of the secret left on screen (exit 130).
- **The copy on the PATH:** a scratch install on Docker made it, a new terminal ran `suiteward version` by name, and a purge with the typed id offered its removal. The copy was renamed `suiteward.exe.old`, because Windows cannot delete a program that runs, and that file was deleted by hand.
- **The release:** `v0.4.0-alpha.2` carries `install.sh` and the signed binaries of the five platforms; its Windows binary matches `SHA256SUMS` and prints its version and image digest.

**Still to be seen.**
- macOS: the screens, the arrow keys and Ctrl-C on Terminal, the setup window, and the status address from the Mac, with the runbook that the owner keeps with the notes of the phase, which is not in the repository.
- The fresh install again, as a new user, with `v0.4.0-alpha.2`: the account choice with a real organization, the hidden paste after 2 minutes and the ruleset pause.
- An upgrade that refreshes the copy on the PATH, and the trimming on a small window.

**Known limits.**
- **The organization look-up checks only that the account exists and is an organization.** It does not check that the user may create Apps there (UX-6 asked for it): the call has no authentication, which also limits it to 60 requests an hour for each address. A failure that is not a 404 warns and goes on, and the check of the conversion is the last one (`internal/installer/github.go`).
- **The macOS setup window stays open, cleared,** when setup ends: the installer cannot close a Terminal window. The installer waits for it up to 15 minutes.
- **A Windows setup window that is killed by force clears nothing,** so what the secret showed stays on its pane until it is closed.
- **The copy on the PATH is as safe as the folder it is in:** a program that runs as the user can replace it, the coding agent of the co-located tier included. It is the program that offered it, and nothing verifies it again.
- **Keys:** an arrow that a slow link splits across two reads is lost, a numbered list that is longer than the page (the fallback of a list that cannot read keys) shows its last rows, and a name that holds a comma cannot be typed in a multiple choice. Each has a `shortcut:` note in `internal/installer/ui`. A list picked with the arrow keys, `Select` or `MultiSelect`, scrolls with its highlight.
- **The summary of a small window** trims its warnings and then its other rows, and keeps four rows by name, `Tier`, `Instance`, `Status` and `Doctor`: the names are spelled in `internal/installer/ui/render.go`, because a summary is rows and warnings and says nothing about which of them matter (a `shortcut:` note). Everything is printed again when the screen closes.
- **Plain mode has no explanations and no closing doctor:** an install that no terminal runs prints `suiteward doctor` as the next command.

**Release notes** of `v0.4.0-alpha.2`, the release that carries this phase. Its image index digest is `sha256:e7e4cfccdf83f19b20ba08467a1f025079a9ef1fb88522b7e20d92e6bbab89d9`.
- *New:* each question of the installer explains itself on a page of its own; choices are made with the arrow keys; setup opens in a window of its own on Windows and macOS; the install ends with the result of `suiteward doctor`; on Windows the install offers to put `suiteward` on the PATH; `suiteward version`.
- *Changed:* the default ports are 27081 (HTTP) and 27091 (MCP). A stack that exists keeps its ports, and an upgrade never moves one. A settings file without both ports is refused. The revision comment says how to open the report in a new tab.
- *Know before you upgrade:* a host or a PC that `v0.4.0-alpha.1` installed keeps 8081 and 8091. The ports in your own scripts and port forwards stay as they are.

## Not in this phase

A Windows one-line install, starting the Podman machine at logon, a check of the user's permission to create Apps in an organization, an `install.ps1`, notarization, and everything that [M1.13](M1.13.md#not-in-this-phase) left out.
