# M1.2: Runtime

**Goal:** a runnable `suiteward serve` that loads configuration, migrates, composes the PostgreSQL unit of work and the artifact store, runs River workers whose jobs are enqueued in the same transaction as the governance write, delivers publications through an outbox, and shuts down gracefully.

**Decisions:** D-RUNTIME (accepted).

**Exit:** the binary starts against a fresh database, processes an enqueued job end to end, survives a restart without losing work, and stops within the configured timeout; real PostgreSQL tests in CI; the same image passes a smoke run on both [verification targets](../README.md#verification-targets).

## Tasks

- **M1.2-C0 Contract** (orchestrator): add `Enqueue` and `Outbox` to the `Tx` port in `docs/contracts/persistence.md` and the outbox table (mutable delivery state: attempts, next attempt, terminal state). Freeze before the others start.
- **M1.2-A Configuration** — owns `internal/config/**`. Environment variables plus file-mounted secrets; validation errors name the setting and never print secret values. Tests for required, defaulted and invalid settings.
- **M1.2-B Transactional jobs and outbox** — owns `internal/adapters/postgres` additions, a new migration `00002_outbox.sql`, and `internal/adapters/river/**`. River job insertion inside `UnitOfWork.Do`; outbox rows written with the governance fact; a relay worker with bounded retries and a visible terminal state. Tests: rollback removes both the fact and the job/outbox row; a worker crash re-delivers; terminal state after the retry limit.
- **M1.2-C Composition and lifecycle** — owns `cmd/suiteward/**`, `internal/app/**`. `serve` command, migration on start, health endpoint (Chi), signal handling, graceful shutdown with timeout. Tests with a real database: start, health, stop within timeout, restart resumes pending jobs.
- **M1.2-D Packaging and deployment** — owns `deploy/**`, the image build file, and a deployment workflow. One OCI image built in CI and published to the registry chosen in D-DEPLOY; a local Podman definition (co-located) and a Podman quadlet unit for the remote host (isolated); an approval-gated GitHub Actions deployment to the remote host; a smoke script (health, migrate, one job end to end, restart) run against both targets. Builds on the S1 deployment findings.
- **M1.2-I Integration** (orchestrator): phase checks, CI service wiring if needed, dual-target smoke results in the PR.
