# M1.9: Scope discovery

**Goal:** a new user gets a declaration that covers their tests, and SuiteWard tells the owner when a PR adds tests outside the scope.

**Decisions:** [D-SCOPE-DISCOVERY](../decisions.md#d-scope-discovery-suggesting-and-widening-the-scope) and the `suggest` verb in D-COMMANDS, accepted 2026-10-17. The research behind them is summarized below.

**Exit:**
- Over SuiteWard's own file list, the suggestion covers every `*_test.go`, all of `testdata/` and `codecov.yml`, without being cut.
- On the co-located target with a release candidate, live:
  - a `propose` without a declaration suggests include and runner patterns and warns about mixed files;
  - a PR that adds a test outside the scope gets the scope notice, and committing its declaration and approving it promotes the next version;
  - a PR that edits `.suiteward.yml` and misses a test gets a review suggestion whose "Commit suggestion" works;
  - `/suiteward suggest` answers after V1;
  - a reduction lists what it removes.
- The guide covers widening the scope and rotating the App key with a fingerprint check.

## Research (2026-10-17)

- **Codecov** does not detect test files. It finds report files, skips a list of vendored directories, and asks the runner which tests exist. Only the ignore list carries over, because SuiteWard does not run code.
- **Path-only prior art** (Linguist and go-enry, Semgrep, CodeQL) uses curated patterns that match at any depth. Tools that need exact results (Sonar on Maven, Gradle and .NET; Launchable) read the build or runner configuration. That reading is after the MVP here.
- **Runner precedence is a bypass.** pytest uses the first config file it finds, and Mocha and PHPUnit work the same way. The suggestion therefore names the higher-priority files that do not exist yet.
- **GitHub's editor** fills in content only on `/new/`, not on `/edit/` (checked 2026-10-17). An existing `.suiteward.yml` therefore gets a copyable block and the edit link, or a review suggestion when the PR's diff already touches it.
