# M1.01 persistence verification

The [frozen contract](../contracts/m1-01.md) defines the consumed PostgreSQL/filesystem boundaries. The [execution record](../plan/executions/M1.01.md) and its machine-readable evidence preserve observed task checkpoints, ownership, independent reviews and exact final revisions. Git ancestry and JSON consistency are checked by CI; those checks do not independently establish historical test execution order.

## Real adapter scenarios

The schema tests use actual PostgreSQL 18.6 with a unique schema per fixture. They cover fresh installation, repeat/concurrent migration, populated migration 1-to-2 upgrade, failed migration-body rollback, immutable history UPDATE/DELETE/TRUNCATE rejection, scoped/kind foreign keys, deferred orphan-effect rejection, exact unsigned revision advancement/exhaustion and generated query round trips. Generation verification independently compares a fresh sqlc output directory with the entire versioned filename/content inventory.

Governance tests use pgx transactions and the existing application/domain decisions. They verify original consent and historical source aliases, exact durable operation identities, revalidation after revocation, competing promotion writes, actual SQL statement and deferred commit failures, complete rollback of pointer/version/receipt/audit/publication effects, and safe identity reuse after rollback. Initialization is trusted, insert-only and unbaselined; incomplete migration sequences are not ready.

Checkpoint regressions preserve legal pending-priority requests whose waiting target closes before reconciliation. Both an active and an integrated former proposal retain the exact generation/request; unresolved observations remain unchanged, withdrawal cannot activate the closed target, and a former-merge observation can reconcile the state and round-trip again. Forged scopes, carriers, receipts, absent former ownership and other pending-target states remain rejected.

Composed tests use the actual filesystem verifier with PostgreSQL. Missing proposed raw content prevents promotion. Hash-valid raw entries permit promotion without storing the manifest metadata digest as a raw blob. Corrupt or missing referenced bytes prevent current reads, explicit history reads and exact replay. A two-version scenario leaves current v2 healthy while corrupting/deleting only v1: v2 remains readable, while v1 receipt/history fails. Candidate publication cannot repair corrupt existing objects. Independently published content can survive database rollback as an unreferenced object; retry creates the first durable promotion. Two requests held at their coherent read boundary race through real transactions and leave exactly one winning canonical version with complete effects.

Filesystem tests use real disk operations, independently staged concurrent writers, no-clobber publication, duplicate byte revalidation, interruption/cancellation and private per-store wrappers for operational failures. They verify sync and close before publication, preserved error causes, owned-stage cleanup, safe retry after postpublication cleanup failure, and rejection of nonregular/symlink objects. Two Windows symlink cases require unavailable host privileges; only actual Linux execution supplies their evidence. Linux-only constructor cases remove the test's own empty working directory and deny write permission on its own parent directory; an actual nonprivileged Linux run verifies resolution/creation failures, preserved causes and absent artifact roots. Windows and root-user skips do not establish those permission guarantees. No test-only failure hook is exposed as a production API.

## Execution boundaries

`dev.ps1 check` remains service-free. `dev.ps1 persistence` selects only the checkout's own ignored database identity and runs generation verification plus real integration tests. Linux CI adds race/coverage with a healthy isolated PostgreSQL service; native Windows/ Linux Go jobs retain portable verification and generation freshness. Coverage excludes only the existing dedicated dbgen directory and retains the accepted 99% floor, 0.25 percentage-point maximum decrease and 90% patch requirement.

These adapters establish local transactional authority and immutable bytes. They do not establish remote check delivery, authenticated GitHub identities, production execution, backups/restore, cross-resource atomicity or directory durability across power loss. Publication/acknowledgment rows are durable intents. Trusted instance/host configuration is outside candidate control; a malicious host administrator is outside this phase's guarantees. A repository may contain tests but cannot redefine its own canonical test contract.
