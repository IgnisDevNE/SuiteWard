# M1.15: installer leftovers, the live findings, scope discovery from config files

**Goal:** close what M1.14 left in the installer, fix what the live checks of `v0.4.0-alpha.2` find (on macOS, by an outside tester, and on Windows, by the owner), and, in parallel and in packages the installer does not touch, let the scope suggestion learn where the tests are from the project's own config files. The governance of this repository changes only by the D-SELF-SCOPE entries below, approved by the owner like any protected change.

## Owner decisions (2026-10-25)

1. **The phase.** The installer leftovers, the live checks and a wave reserved for the live findings, with scope discovery as the post-MVP track.
2. **`suiteward scope add`** answers the owner's question Q2 (a command to add folders that the suggestion missed): a local command in a checkout, for a user or an agent, that adds patterns to `.suiteward.yml` as text. The change still needs the owner's approval on its pull request.
3. **TOML through a dependency:** a mature, fuzzed TOML library with no transitive dependencies reads `pyproject.toml` and `Cargo.toml`.
4. **Config files are read wherever a suggestion is built:** `propose`, `/suiteward suggest` and the scope notice of the checks job, so the notice and `suggest` agree. This amends D-SCOPE-DISCOVERY, where detection was path-only. The reads are bounded in size and number, and content from a pull request only adds to a suggestion.
5. **D-SELF-SCOPE, accepted:** `scripts/install_test.sh` and `deploy/smoke_test.sh` join `include`, and `scripts/install.sh` and `deploy/smoke.sh` join `runner`.
6. **D-RESTORE-INPLACE, accepted for the alpha:** the in-place restore stays, with its typed instance id and its safety backup; the recovery mode of ADR 0020 waits with the remote backups.
