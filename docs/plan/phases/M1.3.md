# M1.3: Scope, inventory and existing-baseline bootstrap

**Goal:** turn a repository's `.suiteward.yml` and file tree into an exact protected inventory, with protected defaults that a candidate cannot weaken, and establish the first canonical contract from a pinned main-branch commit.

**Decisions:** D-SCOPE, D-SCOPE-DEFAULTS, D-APPROVAL-CONTEXT (accepted); ADR 0013 amendment (protected defaults include `.github/workflows/**`, test runner configuration, and test scripts).

**Exit:** given a repository tree, SuiteWard produces a deterministic inventory and proposal revision; scope reductions are classified as protection reductions; bootstrap creates the first canonical through the existing-baseline path.

## Tasks

The orchestrator split the original A and C tasks when the phase started (2026-10-11): the pattern matcher has no dependency and is the first real [Orbit](../orbit.md) task, and the proposal revision write consumes only existing contract types, so it runs in the first wave.

- **A1** — gitignore-style patterns (D-SCOPE): anchoring, directory-only patterns, `**`, case sensitivity, rejection of negation, backslashes and dot segments. Table tests.
- **A2** — parse the declaration (YAML; `include`, `exclude`, `runner`), merge with the fixed defaults of D-SCOPE-DEFAULTS, compute the declaration digest over raw bytes plus normalized rules, reject invalid declarations while the governing scope stays in force. Table tests including invalid declarations and reduction attempts.
- **B** — from a source tree abstraction (interface; filesystem fake in tests), compute the protected inventory, its manifest and scope digest, and the covered inputs; reject symlinks and submodules inside scope; classify changes against the canonical contract (unchanged, implementation-only, protected change, scope reduction).
- **C1** — the first proposal write path outside `Seed`, per the contract: create or revise a proposal inside the unit of work, no revision for unchanged coverage, conformance and PostgreSQL tests, and the test where a proposal blocked by `CanonicalChanged` is revised against the new canonical and promotes only after fresh exact approval (R1 used a stand-in proposal because no revision write path existed).
- **C2** — create a proposal revision from an inventory and run the existing-baseline bootstrap from it.

Added during the phase: **A1-fix** and **A2-fix** (review findings on the Orbit runs: a trailing `/**` needs a component below its base as in gitignore, the zero `Pattern` never matches, YAML merge keys are rejected), and **A3** (`Pattern.MayMatchBelow`, `Scope.MayCoverBelow`: whether a scope may cover something below a directory, so the inventory rejects links inside the scope without pattern internals). A1, A2 and B ran in Orbit as prompts #6, #7 and #9 (see [Orbit results](../orbit.md#m13-results)).

## Outcome

Completed 2026-10-11 on `phase/M1.3`.

- `internal/domain/scope`: gitignore-style patterns, the `.suiteward.yml` declaration (YAML v1: `version`, `include`, `exclude`, `runner`), the effective scope with the fixed defaults of D-SCOPE-DEFAULTS, its digest over raw bytes plus normalized rules, rule-level reductions, and `MayCoverBelow`.
- `internal/application/inventory`: the protected inventory of a pinned source tree (symlinks and submodules inside the scope are rejected; only covered files are read), evaluation under the governing scope, and classification of a candidate as unchanged, protected change or scope reduction.
- `internal/application/governance`: `ReviseProposal` and `Tx.AppendProposalRevision` (fake and PostgreSQL), and `ProposeBaseline`, which stores the covered bytes and creates the baseline proposal for `Bootstrap`. The re-revision after `CanonicalChanged` replaces R1's stand-in proposal.
- Evidence on real adapters: PostgreSQL and the filesystem store run the baseline proposal and the bootstrap of the first canonical, with the revision and its assessment seeded.

Limitations and open points:

- Assessments have no write path until M1.6, so the PostgreSQL bootstrap test seeds the revision and its assessment; the in-memory fake accepts an assessment for a revision that does not exist yet, which PostgreSQL rejects, and one fake test relies on it (commented at the seeding site).
- `ParsePattern` accepts patterns with newlines or control characters (they never match a valid path).
- YAML tags on the root mapping and on lists are ignored, as before the merge-key fix.
- Excluding `.suiteward.yml` is classified as a scope reduction (the rule-level check is syntactic), although the file stays covered: conservative, to be confirmed by the owner.
- The `Tree` interface should require leaf-consistent entries (no file below a link or a submodule path); a git adapter cannot produce them, a filesystem adapter might.
- The governing scope for `Classify` will be rebuilt from the canonical's `.suiteward.yml` bytes in the content store when the synchronization phases need it; nothing in M1.3 does that yet.
- Orbit prompt #8 ran with content that differed from what was queued and was retried automatically; #9 replaced it.
- A baseline whose bytes change under the reader, or that is rejected because a canonical exists, can leave blobs in the content store as harmless orphans; there is no garbage collection yet.
- `TestProbeWithoutAServerTimesOut` (`internal/app`) failed once during C2 with a local TCP write timeout and passed on rerun; it is unrelated to this phase and is recorded as possibly flaky.
- In C2, the commit after the implementation (`test: propose the baseline again under the seeded origin`) changes a fixture value without changing what the test proves; the test-first order is otherwise intact.
