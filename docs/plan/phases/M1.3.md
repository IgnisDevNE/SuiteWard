# M1.3: Scope, inventory and existing-baseline bootstrap

**Goal:** turn a repository's `.suiteward.yml` and file tree into an exact protected inventory, with protected defaults that a candidate cannot weaken, and establish the first canonical contract from a pinned main-branch commit.

**Decisions:** D-SCOPE, D-APPROVAL-CONTEXT (accepted); ADR 0013 amendment (protected defaults include `.github/workflows/**`, test runner configuration, and test scripts).

**Exit:** given a repository tree, SuiteWard produces a deterministic inventory and proposal revision; scope reductions are classified as protection reductions; bootstrap creates the first canonical through the existing-baseline path.

## Tasks

- **M1.3-A Declaration parsing** — owns `internal/domain/scope/**`. Parse the declaration (gitignore-style include/exclude, case-sensitive), merge with protected defaults, reject symlinks and submodules inside scope, compute the declaration digest over raw bytes plus normalized rules. Table tests including invalid declarations and reduction attempts.
- **M1.3-B Inventory** — owns `internal/application/inventory/**`. From a source tree abstraction (interface; filesystem fake in tests), compute the protected inventory, its manifest and scope digest, and the covered inputs; classify changes against the canonical contract (unchanged, implementation-only, protected change, scope reduction).
- **M1.3-C Proposal revisions and bootstrap** — owns use-case additions in `internal/application/governance/**`. Create a proposal revision from an inventory inside the unit of work, and run the existing-baseline bootstrap. Conformance and PostgreSQL tests for the new writes (the `Tx` port gains the needed write methods through a contract update by the orchestrator). Include a test where a proposal blocked by `CanonicalChanged` is revised against the new canonical and promotes only after fresh exact approval (R1 replaced it with a stand-in proposal because no revision write path existed).
