# H1: Orchestration v2 and Go hygiene

**Goal:** run SuiteWard work with a cheaper, sharper orchestration — Sonnet orchestrating, an Opus advisor at critical moments, Haiku scouts for discovery, deterministic hooks for mechanical decisions, Memtrace-first navigation with gopls as fallback — and clean the code of defensive nil checks and needless code, enforced by lint.

**Why:** the Opus-orchestrated, read-everything workflow spent its most expensive model on mechanical work, and generated Go code tends to accumulate guards that hide impossible states (`if x == nil { return }`, `return nil, nil`, swallowed errors) and more code than needed.

**Exit:** the orchestration configuration is versioned and verified in a fresh session; every nil check in `internal/` is classified and either justified or fixed (behavior changes test-first); ponytail audit findings that preserve the invariants are applied; `golangci-lint` runs clean in `check` and CI; `check` and `persistence` pass.

## Rules

- [Nil checks](../../development-guide.md#nil-checks) and "least code that does the job" are in `AGENTS.md`; `sw-reviewer` checks both.

## Tasks

**Wave 1 — orchestration (orchestrator session, before reloading)**

- **H1-O Configuration** (orchestrator): `.claude/settings.json` (main model Sonnet with high effort, `advisorModel: opus`, default subagent model Haiku, ponytail pinned to `v5.1.0` / `9cc65d03aa2da1db7121b912d03596409ee340b8`, hooks), `.mcp.json` (gopls), `sw-scout` agent, updated `sw-implementer`/`sw-reviewer`, `AGENTS.md`, `docs/plan/orchestration.md`, `docs/development-guide.md`.
- **H1-T Tooling** — hooks `scripts/hooks/{go-format,repeat-failure}.ps1` with `scripts/test-hooks.ps1`, pinned `gopls` and `golangci-lint`, `./scripts/dev.ps1 lint|gopls`, `scripts/gopls-mcp.ps1`.
- Memtrace returns to the stable channel on the developer machine (outside the repository).

**Wave 2 — hygiene (new session, run by the new orchestration)**

- **H1-A Inventory** (`sw-scout`): every `== nil` / `!= nil`, `return nil, nil`, swallowed error and empty `default` in `internal/`, classified as boundary (keep), contract-optional (keep), redundant after a validated constructor (remove), or silent swallow (fix).
- **H1-P Ponytail audit** (orchestrator): `/ponytail-audit` over the repository; accept only simplifications that keep validation, error handling and the governance invariants.
- **H1-L Lint** — `.golangci.yml` (version 2, `linters.default: none`; `govet`, `staticcheck`, `errcheck`, `unused`, `ineffassign`, a small `revive` rule set, `gocritic` diagnostic tags; formatters `gofmt` and `goimports`; build tag `integration`), lint wired into `check-go.ps1` so CI runs it on Windows and Linux.
- **H1-B Fixes** (`sw-implementer`, one worktree per package group: domain, application, adapters): apply H1-A, H1-P and H1-L findings; RED test first whenever behavior changes; `sw-reviewer` per task; advisor review before the phase PR.
